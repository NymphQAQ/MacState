# 显示器亮度（杂项）

参考项目：[Crisp](https://github.com/didriksg/Crisp)，MIT，作者 Didrik Galteland（版权通知随应用资源打包：`Resources/Web/Crisp-LICENSE.txt`）。

## 设计

「杂项」→「显示器亮度」按物理显示器列出名称、可选控制模式（系统背光、DDC/CI、软件调暗、不可用）、实时滑杆和百分比。macOS 内建或兼容 Apple 显示器优先调用运行时加载的 DisplayServices；Apple Silicon 外接屏通过 DCPAVServiceProxy + VESA DDC/CI VCP 0x10；**读取 DDC/CI 亮度失败时不会自动认定硬件不支持写入**。找到可确认的 DDC 通道时显示「DDC/CI 待读回」，百分比显示「—」而不是假装 50% 是实测值，只有用户拖动滑块才尝试硬件写入；写入确认后显示 DDC/CI，连续三次用户更改均写入失败时才降级到 **软件调暗**（CoreGraphics 显示器色彩传递表），不伪装为硬件背光。软件调暗最低保留约 12% 画面，防止完全黑屏；在本应用正常退出时恢复修改前该显示器的色彩表。它与真实物理背光不是一回事，也不会提升最高硬件亮度。

打开页面只读取能力，**不会自动写入亮度**；用户开始拖动滑块时第一条亮度命令立即发送，连续拖动期间约每 **85 毫秒**发送最新值，松手时确保最终值提交，**无需等松手才开始改变亮度**。同一瞬间的高频鼠标事件会合并，后端 DDC/CI 串行工作队列也限制两次写入开始的最小间隔为约 85 毫秒；等待硬件通道时会舍弃过时的目标，仅发送最新滑块位置。每台显示器使用系统 UUID 作为前后端 ID，丢失或不匹配的屏幕拒绝写入。后台序列队列处理可能缓慢的 I2C 读写；滑动过程采用最后一次请求优先，防止积压大量过期的 DDC 指令。每次刷新重新匹配 DDC 通道，「重新检测」按钮还会清除既往的硬件写入失败状态，方便重试；对多个显示器仅使用可以确认身份的匹配关系，不猜测通道编号。VCP 读帧同时检查命令、返回结果、最大值及校验和。

刷新可重新检测显示器。控件采用 MacState 已有「杂项」的卡片设计；标准宽度显示器信息与滑杆并列，窄窗口自动换行。WebKit 只允许本地受信任页面通过 `getDisplayBrightness` 和 `setDisplayBrightness` 调用原生 API。整个功能不要求新的系统权限，也不进行显示器断开、分辨率更改或管理员操作。

## 限制

- MacState 的软件调暗依赖系统允许设置 ColorSync 传递表；某些显示器、HDR 模式或系统设置可能拒绝或覆盖设置，UI 会报告失败。
- DDC/CI 读取可能失败而硬件写入依然有效。MacState 仅在明确匹配到物理 DDC 通道时才允许用户手动尝试写入，初始滑块值是参考位置，当前百分比显示「—」；写入成功仅表示 I2C 操作返回成功，不代表可靠读取到屏幕当前亮度。写入失败会作有界重试，连续三次用户更改失败才切软件调暗。多屏配对不确定时仍不盲写。
- 通过强制结束进程、崩溃或掉电而退出时，macOS 不一定执行应用的退出恢复逻辑。用户仍可回到屏幕设置或重新登录以恢复系统色彩状态。
- 不复制 Crisp 整套显示管理系统；仅参考其显示器亮度分流与 DDC 帧校验方式，并单独保留 MIT 许可声明。

## 验证

- `DisplayBrightnessTests` 覆盖取值 0…100%、DDC VCP 报文、校验和、错误响应、单屏／多屏匹配和软件安全亮度下限。
- WKWebView 测试检查杂项页面显示模式标签、可用／不可用滑杆、显示器切换、用户明确拖动才触发后端命令，不读取即写入。
- 对当前设备只读探测：M1 Pro 外接 `DM73u pro`，DisplayServices 无原生背光。已安装 Crisp 的 `crispctl display list` 报告 `brightnessBackend=ddc`、亮度约 48.7%；其系统日志还确认 **DDC 硬件写入已获确认**，同时反复出现 DDC VCP 0x10 读数失败。MacState 修正后只读探测在不同测试次序分别取得 `mode=ddc`（约 48%）与 `mode=ddcUnverified`（当前亮度未知），不再错误降级到 software。自动测试未写入真实亮度。
