# MacState UI / UX 全面重构提案

日期：2026-11-02。状态：设计审查与建议，尚未实施。

## 目标与审查依据

将现有的监控面板、存储分析和桌面工具组织成有清晰任务路径的 macOS 工作台。优先解决导航、首屏信息、结果空间和操作反馈，再调整视觉。保留菜单栏唤起与后台运行，不新增聊天首页或第二套 UI 框架。

本轮读取了项目路线图、desktop-design 与 storage-workbench 规格、截图编辑规格，以及 desktop-agent-ui、apple-design 技能；检查了 Web 页面、样式、数据接收函数、AppKit 窗口和原生截图工具的相关源码。

在隔离浏览器中以样例数据检查了总览、进程、传感器、网络、存储、使用记录、截屏、快捷工具和设置。主要尺寸为 1200×850，存储另检查了 600×420。浏览器模拟不能代表 AppKit 材质、真实输入法、真实数据性能或实机功能验收。原生 OCR 设置参考了已有隔离渲染截图，并用当前源码核对结构。

上一轮已完成字号收敛、细边框、紧凑模式、焦点、减少动态效果和部分响应式处理。这些作为本轮基线保留，不计作新的重构成果。

## 已观察到的结构问题

1. 一级导航有八个功能和设置；进程、传感器、网络分别占据一级入口，监控内容的组织方式与存储、工具混在同一层。
2. 全局标题栏几乎总是显示采样状态、导出、设置、自定义展开和关闭。设置与侧栏重复；截屏等页面的全局 JSON 快照导出缺少明确上下文。
3. 存储在应用标题下叠加卷级工具栏、工作区导航、子功能导航、批量操作、搜索、类型筛选及列表工具。600×420 样例中，首屏只能看到结果容器顶部，文件行需要外层滚动才能访问。
4. 总览在四张主卡之后继续显示逐核占用和全部详细指标；摘要、排查入口与低频原始数据的优先级接近。
5. 进程表默认十列，并在每行重复显示 30 秒平滑功耗。比较主要指标和阅读细节争用空间；进程详情使用阻断式弹窗。
6. 传感器以同权重卡片展示大量 SMC 原始键名。网络接口也采用固定卡片布局，接口数量变化时比较效率较低。
7. 使用记录将会话、曲线、摘要、应用能耗、覆盖率及进程明细放在同一纵向页面，统计范围和阅读路径需要更明确。
8. 截屏同时提供“截屏设置”按钮和“截屏选项与快捷键”展开入口；历史卡片重复展示多组操作。
9. 设置仍是很长的全宽页面，采样、外观、状态栏样式、栏目编辑、文件关联和数据说明集中排列。玻璃说明及实现细节占据较多首屏空间。
10. 原生截图及翻译设置不在上一轮 Web 统一范围内：存在 8–11pt 控件文字、固定深色设置窗口，以及密集的固定坐标表单。这里记录的是源码事实，尚未进行本轮原生渲染或实机验收。

## 建议的信息架构

| 一级入口 | 内容与迁移 |
| --- | --- |
| 总览 | 当前状态摘要、少量趋势、进入对应排查页面的入口 |
| 活动监视 | 进程、网络、硬件传感器作为内部视图；保留全部原始数据 |
| 存储 | 卷与索引、文件浏览和分析、应用与专项、历史与增长 |
| 使用记录 | 当前与历史会话、电量/功耗、前台应用与进程明细 |
| 截屏 | 新建截屏、最近截图；继续使用原生选区和编辑器 |
| 快捷工具 | 显示器亮度、调度中心及现有快捷键配置入口 |
| 设置（底部） | 通用、外观、状态栏、监控与记录、截屏与翻译、文件与权限 |

导航合并不取消独立视图，也不使网络、传感器只能从总览访问。保留直接跳转、现有快捷键和页面恢复。宽窗保留文字导航，窄窗可收合，记录用户选择；仅在可用空间不足时自动适配，并提供可读的名称与键盘入口。

## 更改清单与具体做法

P0 为结构与主要任务路径，P1 为各页重构和视觉落地，P2 为最后的细节与动效。优先级不是已经完成的状态。

| 优先级 | 范围 | 具体修改 | 结果标准 |
| --- | --- | --- | --- |
| P0 | 窗口外壳 | 明确“菜单栏唤起的持久工作台”定位；标题与当前对象合并，使用符合 macOS 习惯的窗口控制和工具栏。区分当前“填满可用区域”与系统全屏，避免同名异义 | 收起继续后台；点击外部不关闭；Esc 先退出局部操作，再处理窗口；现有位置和大小恢复保留 |
| P0 | 全局导航 | 按上表收敛为六个业务入口，设置置底；活动监视内部切换进程、网络和硬件 | 所有既有入口都有明确迁移位置，返回后恢复筛选、选择与滚动 |
| P0 | 页面工具栏 | 每页只展示当前任务相关操作；导出明确对象和范围，设置保持一个主入口；采集耗时、版本和数据来源移到状态详情或关于页面 | 截屏页不出现无解释的系统 JSON 导出；结果列表获得更多可视高度 |
| P0 | 存储导航与布局 | 将多排工作区/子页按钮重组为可收合的分组导航；宽窗显示目录，窄窗由一个导航按钮展开。主区保留卷选择、路径和一行上下文工具栏 | 600×420 默认首屏直接看到至少 160px 高的结果区，不需要先滚过多排导航 |
| P0 | 存储查找与筛选 | 搜索框明确“整个卷/当前目录”范围；类型、大小等筛选集中到筛选菜单，已启用条件显示为可移除标签；不把全部类型永久铺开 | 搜索范围始终可见，清除条件一步可达，旧查询和分页能力完整 |
| P0 | 存储维护与安全操作 | 索引状态收成“已就绪/同步中/受限”等摘要；重建索引移入维护菜单。选中后才出现批量动作，清理预览显示影响对象和现有风险信息 | 保留逻辑/物理占用口径、硬链接去重、保护规则和原生确认；不暗中启用当前隐藏的清理入口 |
| P1 | 总览 | 保留少量主要指标和统一时间窗；逐核负载与原始指标进入详情。指标点击进入对应对象详情，提供返回路径；不为每一行默认绘制趋势 | 首屏能快速找到当前读数与排查入口；无可靠依据时不生成“健康评分”或故障判断 |
| P1 | 活动监视：进程 | 默认保留进程、CPU、内存、功耗等主列；PID、线程、用户及读写等由列菜单配置。详情改为非阻断检查器，窄窗使用独立详情层 | 保留全部十列能力、暂停/恢复、排序、查询和分页；实时刷新不使正在阅读/操作的行跳走 |
| P1 | 活动监视：网络/硬件 | 网络先显示当前活动接口摘要，再用列表比较全部接口；传感器按温度、风扇、功率分组。可靠映射时显示易读名称，同时保留 SMC 原始键 | 未知键不猜测名称；VPN/物理接口统计范围、不可用与未连接状态清楚区分 |
| P1 | 存储文件结果 | 文件列表与空间地图共享当前目录、卷和选择上下文；应用/开发者/浏览器等专项复用结果表和详情检查器；长路径允许查看与复制 | 保留目录下钻、名称搜索、文件类型、大文件、重复、媒体、应用与全部专项、历史、权限、Finder 和现有文件操作 |
| P1 | 使用记录 | 将记录选择和时间范围固定在工具栏；曲线与应用列表建立清晰对应。主列表比较前台时长、平均估算功耗和累计耗能，覆盖率及进程放到展开详情 | 保持会话真实边界、旧算法标识、缺失/睡眠空段与无电池模式；整机温度不误标为应用温度，不补造过去记录 |
| P1 | 截屏首页与历史 | 建立清楚的“新建截屏”主操作与模式选择；显示器、延时等放在相应模式附近。设置只保留一个入口；历史以缩略图和预览为中心，按日期组织 | 编辑、复制、Finder、废纸篓均保留；此前确认的四图标单行操作作为基线；忙碌状态只禁用确实冲突的动作 |
| P1 | 原生编辑器、OCR、长截屏 | 工具选择、属性和最终输出分区；属性仍紧凑就近显示，必要时扩大面板容纳可读文字。OCR 的“翻译”和“原文/译文切换”使用不同控件，语言和服务在操作前可见 | 保留选区、取色、全部标注、撤销、长截屏双向拼接/预览、原位流式译文、选择、复制与滚动；不把编辑画布迁入 Web |
| P1 | 设置与翻译服务 | 设置改为分类导航。常见设置先显示，技术说明放进详情。状态栏栏目编辑与实时预览并列；翻译服务按系统/本地/API 展示各自需要的字段 | 本地模型和密钥信息保留；本地环境准备/修复、测试和释放内存可达；API 发送范围明确；草稿保存语义不被自动保存替换 |
| P1 | 快捷工具 | 显示器按设备用紧凑行展示滑块和数值，调度中心保留直接打开。快捷键配置通过同一设置入口管理 | 滑块跟随拖动即时反馈；保留系统背光/DDC/软件调暗及未知读数区别，不把发送命令当作设备已成功执行 |
| P1 | 视觉与材质 | 使用系统字体与中文回退，统一蓝色强调、语义状态色及数字对齐。正文以 14、辅助以 12、标题 20、关键数值 28 为基准，每页不超过四档。列表用分组/分隔组织，减少重复卡片 | Web 不低于 12px，原生 UI 标签不低于 12pt；用户可选的截图标注字号与状态栏字号不受这一下限强制修改 |
| P1 | 跨页状态 | 统一首次加载、刷新、空结果、无权限、不支持、部分数据、失败、取消中和已停止；有旧结果时保留旧结果并说明更新时间，失败提供明确重试位置 | 状态绑定真实事件；总量未知时不用伪进度；发出停止请求不等于已经停止 |
| P2 | 桌面交互与动效 | 固化键盘路径、输入法守卫、右键、选择、返回、焦点恢复和按压反馈；普通反馈短而克制，有直接拖拽时才使用可打断的连续运动 | 不修改已有快捷键含义；减少动态/透明度与高对比模式有效；阴影和 Popover 在实际边界不裁切 |

## 技术边界与实现顺序

继续使用 AppKit / WKWebView、离线资源、现有 Lucide 图标和原生 SF Symbols。统一两端图标含义与视觉重量，不为换风格引入 React/Electron 或第二套组件库。继续使用低开销单层原生磨砂和已有可选增强，不增加逐卡片模糊或屏幕采集。

存储继续共享现有元数据索引。哈希、媒体、清理规则和历史使用已有独立扩展数据；不新增全盘扫描器，不为了界面读取所有文件内容。对页面组件的整理不改变统计口径、数据库格式、查询协议和现有安全边界。

实施分为四步：

1. 先做总览、存储文件浏览、设置三屏的可点击结构原型，同时覆盖 1200×850、920×660、600×420。确认任务路径与可视结果空间，再确定最终视觉。
2. 落地共享外壳、导航、工具栏、列表、检查器、状态和设计令牌；以页面为单位迁移，清理旧样式的重复覆盖，避免再叠一整层补丁样式。
3. 迁移监控、存储、使用记录、截屏首页与快捷工具；原生窗口控制、截图编辑器和翻译设置单独成批，避免同时改动窗口生命周期和截图坐标系统。
4. 按实际改动运行相关测试；完成 Release 编译打包、既有固定签名验证并启动。编译成功只代表可构建，功能、性能、布局分别记录证据。只有用户明确要求才进行实机验收。
