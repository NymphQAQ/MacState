# 紧凑索引设计

- directory_paths：整数 ID 与目录完整路径，一条路径只存一次。
- file_records：整数主键、父目录 ID、名称及所有原有属性；根条目单独标记，保留卷显示名称与真实路径的区别。
- entries：兼容投影视图，按需合成完整路径与 parent，现有输出模型不变；常用路径定位、目录分页和大文件候选先通过物理表的整数索引筛选。
- FTS5：复用 file_records 的 ID，保留短中文和字面量搜索编码，不再复制 search_names 和 tokens 原文。增删改触发器与元数据同事务更新。
- 旧库迁移：独立临时数据库从旧库快照复制元数据，建立索引与搜索，核对全部条目属性、任务和元数据，通过后才替换；失败只清理临时库。需防止旧 WAL 套用到新主库。
- 增量事件协调、祖先累计及硬链接算法保持；以 ID 定位代替完整路径索引。
- 后续媒体/哈希/归属/清理规则/历史使用独立扩展表。内部 ID 不作为永久跨历史身份。
- 验证：完整既有测试、迁移失败/完整性与边界路径测试、真实数据库副本迁移和搜索基准；不得改变用户权限。

## 查询约定与后续扩展

- entries 是只读投影，不再允许直接 UPDATE/DELETE。写入使用统一 store 方法，确保聚合和 FTS 同事务。
- 精确路径定位调用 recordID/indexedEntry，目录浏览调用 children；不要对 entries.path 做全表过滤。分页候选应先通过 file_records 的索引限制，再合成路径。
- 唯一索引采用 (dir_id,root,name)，根条目另有 dir_id 部分索引，避免宽目录下查找根条目退化。大文件索引仅存 bytes 与整数 rowid，同大小项目由查询按真实路径排序。
- 名称搜索不依赖类型缓存，文件类型变更立即从统一记录读取；contentless FTS 删除必须提供旧名称的完整编码。
- 清理可释放空间不能直接等同于 st_blocks：APFS 克隆/快照共享空间需在后续清理分析中独立处理。当前优化完整保留既有占用口径。
