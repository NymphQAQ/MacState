# 清理、应用空间、残留与缓存分析

复用现有元数据索引，通过已知目录的直接子项查询与 App 包元数据识别归属。不另建扫描器，不读取用户文件内容。规则版本/范围/风险/启用状态保存在独立扩展表 `storage_cleanup_rules`，元数据索引不依赖该表；代码白名单始终限制可操作范围。当前用户 Library 和所选卷中的 App 包为范围；应用共享组通过签名 entitlement 识别，共享占用单列不重复相加。无法匹配安装应用的项目仅称疑似残留。

界面沿用玻璃与 Avenir Next / PingFang SC，蓝色应用、绿色低风险、橙色需确认、红色高风险。四个页面共用可取消快照，列表可筛选，应用可展开目录明细。清理默认不选择任何项目，先预览路径、风险和索引占用，再原生确认；只允许规则命中的当前用户缓存/日志/疑似残留路径，系统和共享目录仅分析/Finder。运行中应用先退出。移动前复核路径、权限与文件身份，不永久删除。硬链接/APFS/受限目录影响实际释放，移入废纸篓不会立即释放磁盘空间。

实现范围与限制：应用包来自所选卷索引，Library 来自当前用户；只按 Bundle ID、签名组和明确名称匹配，未知路径不能保证归属，残留仅为疑似。共享目录以及系统缓存仅供分析；缓存内常见厂商子目录和容器缓存通过索引读取，不递归扫描。容器缓存与容器累计大小去重，共享占用单列。Xcode DerivedData 为需确认项目。候选不可包含受限/待同步项，清理代码只接受最近原生报告中的路径，每批最多 100 项；会重验已识别运行中 App 与残留注册状态。目录内已有文件的内容变化不一定改变目录修改时间，操作前校验不是内容一致性快照；用户必须先退出相关 App。不自动清空废纸篓，不声称实际释放等于索引占用。
