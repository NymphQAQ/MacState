# MacState

macOS 菜单栏系统监控应用。Swift / AppKit 负责本机数据采集与状态栏，WKWebView 渲染离线 H5 面板，无 Web 服务、无前端依赖、无遥测上传。

## 使用

从 [GitHub Releases](https://github.com/NymphQAQ/MacState/releases/latest) 下载 Apple Silicon ZIP，解压后将 `MacState.app` 拖到「应用程序」。发布包使用临时签名（ad-hoc），未经 Apple 公证，首次打开时 macOS 可能拦截。

双击 `MacState.app`，首次启动自动打开悬浮窗。点击状态栏参数可显示或收起面板，右键参数可打开设置或退出。点击窗口外不会收起。右上角关闭按钮左侧的全屏按钮可填满当前屏幕的可用区域，保留状态栏与程序坞位置，再次点击恢复原大小和位置；全屏时按 Esc 返回原大小，普通状态按 Esc 收起。收起后状态栏与后台采样继续运行。

首次打开时，悬浮窗左右居中、顶部紧贴状态栏。拖动标题区域或侧栏空白可移动，右下角调整大小，位置与大小自动记忆；最小尺寸为 600×420。显示器断开后，窗口会移回可见区域。窗口不置顶，点击窗口外不关闭。磁盘分析的大小与文件数量位于重建索引左侧，无边框；结果列表随窗口大小伸缩，隐藏右侧滚动条，保留滚动与分页。


界面默认使用低开销原生磨砂，透明度为 0%。窗口只有一层 `NSVisualEffectView.behindWindow`，卡片与控件通过 H5 透明底色、圆角和细边框区分，不逐个创建模糊材质，也不逐个计算玻璃布局。玻璃透明度滑块主要调整着色；系统控制原生模糊强度，无法保证与旧自定义透镜的连续模糊、折射完全一致。前景文字和图标不随背景透明度变化。

总览采样刷新会按 ID 保留四张主卡、详细指标分组、指标行及 summary 节点，仅更新数据内容，保留鼠标悬停、键盘焦点和展开状态。使用记录的三张统计卡在低开销和增强模式下均使用独立圆角及间距。

设置 → 采样与外观 → “原生玻璃增强”默认关闭并保存到本机。开启后 macOS 26+ 使用系统 `NSGlassEffectView` 增强窗口及组件的玻璃效果；0% 时不创建透镜，仍使用磨砂。关闭后释放原生透镜并恢复一层背景模糊。旧版 `desktopLensEnabled` 不再启用任何采集，新开关 `nativeGlassEnabled` 独立默认关闭。所有模式均不采集屏幕、不检查或请求录屏权限，不创建自定义 Metal 透镜或屏幕纹理，也没有玻璃渲染定时器。原先的本应用域 `NSGlassTintAmount` 覆盖已移除，遵循系统材质及辅助功能设置。圆角遮罩、拖动和缩放保留；支持深色、浅色和跟随系统。持久化 `glassOpacity` 仍为旧版浓度，界面透明度为 `1 - glassOpacity`。

`dist/MacState.app/Contents/MacOS/MacState --diagnose-glass` 输出当前 AppKit 原生方案及屏幕采集、自定义 Metal 渲染关闭状态。旧 Snell / Metal 光学算法及 MIT 许可证暂留作离线对照实验，位于 `Sources/MacState/Resources/Lens`；GUI 不再使用该管线。测试同时验证默认只有一层背景模糊、无逐卡片效果视图、增强切换不重挂前景内容、0% 不创建透镜，以及低开销模式仍保留窗口拖动布局。

总览采用窄侧栏、四项关键指标、各核心负载窄条与两列分类指标行。CPU 使用绿色、内存与网络使用蓝色、GPU 使用金色、温度与能耗使用珊瑚色图标。点击指标行展开来源、说明、峰值和趋势，实时刷新会保留展开状态；从状态栏唤起时保留当前页面与展开状态，可通过侧栏进入总览。采样刷新时保留四张关键指标卡片的 DOM、焦点与玻璃边界，仅更新数值、说明和曲线；原生材质层仅在实际绘制顺序变化时重新排列，避免刷新闪边。图标使用随应用打包的 Lucide SVG，许可证位于 `Sources/MacState/Resources/Web/icons/LICENSE`。SVG 蒙版以 data URI 内嵌在 `icons.css`，避免 WKWebView 的本地文件蒙版加载问题；修改图标后运行 `rtk proxy node scripts/generate-icons.js` 更新样式。

设置可调整状态栏参数与排列顺序、总览可见指标、采样间隔、历史窗口、深浅主题、紧凑布局、登录启动。设置保存在 `app.macstate.monitor` 的 UserDefaults。登录启动使用系统 SMAppService，建议先将应用拖入「应用程序」再启用；系统可能要求在「登录项」中批准。

侧栏「杂项」可打开 macOS 调度中心，也可选择将全局 `⌘Tab` 改为打开调度中心。快捷键映射默认关闭，勾选立即保存，重启后从保存值恢复；授权未生效不会清除勾选。启用需要「系统设置 → 隐私与安全 → 设备控制和数据访问」（旧版为「辅助功能」）授权 MacState。监听以实际事件 tap 能否建立为准，失败时每 2 秒无弹窗重试，成功后停止轮询；也可点击「重新检测」；其左侧的「打开权限设置」按钮会跳转到设备控制和数据访问（旧版辅助功能）页面，授权由用户手动完成。本地临时签名在重新构建后可能导致旧授权失效；仅关闭再开启旧条目可能保留旧签名，应移除旧条目、重新添加当前应用并授权，或仅重置 `app.macstate.monitor` 的 Accessibility 授权后重新授权。正常重启不会改变签名；正式更新应使用固定代码签名身份。

侧栏「存储」会只读检查完全磁盘访问能力，确认后自动在后台为本地卷建立文件索引；无权限时只提示，不自动申请或修改权限。「打开权限设置」可跳转完全磁盘访问权限页面，由用户授权后点击「重新检查权限」。检测对 Mail、Messages、Safari 做最小目录读取，不依赖私有 TCC 数据库路径，目录不存在等情况与隐私拒绝分别提示。

每个卷卡片显示索引状态、文件/目录数、累计大小、耗时、并行读取上限和当前路径。首次完成时间及耗时会持久保留，“同步变化”和“核对变化”不会将其归零，现有索引仍可分析。首次建立索引需要遍历一次，完成后启用卡片右上角「文件分析」。后台索引不随面板关闭或离开存储页停止。分析直接查询 SQLite，每页 100 项，支持目录下钻、最大 50 个文件、全卷文件名包含搜索及类型筛选，访达定位不提供删除。显示文件名称、后缀、路径、类型、逻辑大小及修改时间，悬停名称可查看创建时间。

索引持久保存在 `~/Library/Application Support/MacState/DiskIndexes/v1/`，不读取文件内容。首次遍历与增量核对按可用处理器数配置 4–8 路并行目录读取，SQLite 写入统一串行；每路最多等待两批，首次遍历每批最多 1024 项、增量核对每批最多 256 项，重叠的父子目录不同时更新，避免删除/汇总竞态；索引数据库采用 WAL、每连接约 8 MiB 页缓存，完整明细无数量上限，每批/页有界。使用每个设备独立的 FSEvents 日志标识和事件游标，常规增删改合并两秒后更新受影响目录及祖先汇总，新目录逐层补入。事件游标仅在该批变化落盘后推进，重启补处理关闭期间的变化；目录通知合并时仅核对受影响子树；事件丢失时保留数据库并核对全卷，游标回绕时重新接入实时流后核对全卷。卷根变化先确认设备身份，身份不符时保留旧索引并提示重新检查。只有缺少有效基线、卷/事件日志身份改变或手动重建时才新建完整基线。索引缓存自身的通知不触发同步写入，防止自通知循环。手动「重建索引」也可重做完整遍历。


文件名搜索参考 MacHunt：独立紧凑目录表保存父路径，统一文件记录保存整数 ID、目录编号、名称及全部分析元数据。搜索与分析共用记录，contentless FTS5 trigram 只保存字符间隔编码的倒排索引，不再复制文件名表和编码原文。支持单字、双字中文及更长关键词的包含匹配，候选再按原名称验证，特殊符号保持字面含义。每次最多取 101 条候选、展示 100 条，不再先全量 COUNT 或按大小排序；有更多匹配时显示“至少”，搜索结果按索引顺序，目录浏览仍按占用大小排列。独立 WAL 只读连接与后台写入分开，输入防抖 80 ms，过时查询可中断。首次遍历批量读取、复用写入语句，大小排序索引及 FTS 统一在遍历后建立。旧索引首次升级时在独立临时库中从现有元数据迁移，逐条核对全部属性，保留任务队列与事件游标；校验和搜索构建通过后才原子替换，失败保留原库并提示，不重新遍历磁盘。卡片显示准备状态，FTS 与文件变更同一事务更新。

本地隐藏文件、隐藏目录及 MacState 索引文件均计入分析。索引文件的占用随正常同步、手动同步和大 WAL 回收刷新。提前跳过 `Library/CloudStorage` 手机/云端映射、`Library/Mobile Documents` iCloud 目录（含本地缓存）、未下载占位文件和其他挂载卷。符号链接不跟随，保留 256 层深度保护。目录占用按实际分配块数统计，硬链接仅计一次，删除计费链接时由剩余链接承接，文件逻辑大小独立保存。系统盘索引 `/System/Volumes/Data`。APFS 快照、克隆共享块、文件系统元数据、权限及跳过项会使结果与卷卡片已用空间不同。无法读取的已有目录保留上次索引并显示提示，直到后续通知或重建成功。

重新打开面板及重启应用恢复上次选择的侧栏页面。索引数据库与其恢复游标跨启动保留，未完成的首次基线会重新建立。


侧栏「使用记录」展示电量曲线、前台应用时间线与本机应用图标、整机平均功耗、已使用时长、满电理论续航，以及各应用按 CPU 内核能量 + GPU 执行时间归属估算的平均功耗、累计 Wh、监测时长和数据覆盖率。点击应用整行可展开主进程及辅助进程明细，按父子关系缩进，显示 PID / PPID、平均估算功耗、累计 Wh 与有效读数覆盖率；包含已退出的进程，相同 PID 的不同启动实例分别保存。超过 100 个实例时分页查看，展开状态、页码和列表滚动位置在自动刷新时保留。进程明细从新版启动后开始积累，旧记录没有采集的部分提示无法补齐。各进程按自己的有效区间平均，平均 W 不能直接相加。应用耗能含后台运行，前台时长单独展示；支持历史切换、应用搜索、时长/功耗/耗能/温度排序、新建记录、删除单条记录与 JSON 导出。无电池设备展示整机功耗曲线。

记录从新版启动后开始采集，保存在 `~/Library/Application Support/MacState/usage-history.json`，每 30 秒自动保存，正常退出时立即保存，最多保留 30 条。充电、电池供电、连接电源分别记录，外接电源的长记录按天分段；重启后恢复当前记录。睡眠、锁屏、停止采集期间留空，不计入使用时间和放电速度；只读电源及前台应用 API，不需要辅助功能权限。

应用合计功耗 =（CPU 内核能量增量 + GPU 归属能量）/ 采样秒数。CPU 保留 [matti/power](https://github.com/matti/power/blob/234179c8084d1ad222a6c1c451f5f191e5af7e4e/src/samplers/proc_rusage.rs) 使用的 `ri_energy_nj` 增量；GPU 读取 IOReport 的设备能量增量，按 IOGPU AppUsage 实际执行时间份额归属。分母包含可追踪的受保护进程及列表外客户端，不按 CPU 评分、前台时长或提交次数猜测 GPU。主值和排序使用当前区间 W，下方另列 30 秒指数平滑；历史按原始能量积分，不使用平滑值。无需 Rust 运行时或管理员授权。

归属优先使用主 PID、应用 bundle 路径、系统责任 PID，再回溯父进程；可合并 Electron 及 WebKit 辅助进程，也包含可发现的后台应用。PID 启动时间变化、计数器回退、首采样、睡眠间隙或权限受限时不计算差分。应用进程不齐时总功耗显示不可用，避免把部分值误当完整应用；显示“已读取 X/Y 个进程”。“其他进程（已读取部分）”只合计未归入应用且读得到的计数，不加入整机差额。停止了旧的管理员评分采集路径，不再按评分分摊整机功耗。

**精度边界：CPU 为内核能量归账，GPU 为执行时间归属估算，不能保证完整应用的物理功耗准确。** 相同时长的计算、渲染、拷贝工作可能耗能不同；GPU 重叠执行、共享静态功耗、DRAM、磁盘、网络和 WindowServer 的服务成本不能精确追溯到调用应用。不用整机差额放大应用读数，也不将 WindowServer 猜测分给前台应用。GPU 客户端变化、缺失或采样窗口错位时暂停相关合计；单 GPU 设备以外暂不归属。进程能量与 GPU 能量/时间按相邻边界采集，门限为区间 5%，最小 30 ms、最大 100 ms，非原子快照。

本机 CPU / Metal / 混合负载各 9 个稳定区间均得到有效读数；纯 Metal 进程从 CPU 计数约 0.053 W 修正为合计估算约 9.289 W。此结果证明漏项已补入，**没有证明 9.289 W 的逐应用绝对误差**。

历史格式升级为版本 5；版本 1/2/3/4 记录完整保留，版本 2 标注旧 CPU+GPU 算法，版本 3 标注旧评分分摊，版本 4 标注旧 power（CPU）算法。升级时结束旧记录并新建新口径的记录，不混合平均值。整机摘要/曲线独立读取 AppleSMC PSTR；仅电池供电且无整机读数时使用电池放电功率，固定来源，来源变化时新建记录。适配器输入 PDTR 可能包含充电，不作为整机功率。应用计数与整机功率不强制闭合。温度采用前台时 CPU 最高传感器读数。满电续航需至少 5 分钟有效放电及 2% 已观测电量下降，排除睡眠等空白期间的电量变化。

状态栏使用两行：名称在上、数值在下。网络上传/下载合为一栏，上传在上、下载在下；旧版上传和下载选择自动合并并保留位置。设置中的「状态栏文字样式」可分别配置名称和数值的本机字体、字号（6–18 pt）、颜色及不透明度，支持自动适应菜单栏文字颜色、实时预览和恢复默认。网络两行都使用数值样式。字号过大时按菜单栏实际高度同比缩小，保证不裁切。

「状态栏栏目」支持自定义名称，每栏下方横排最多 8 个参数，例如名称「CPU」，下方选择「CPU 占用」「CPU 温度」。每栏参数间距可设为 0–40 pt；可添加、删除和移动栏目，调整参数顺序，选择全部已采集指标。网络栏目可切换为普通自定义栏目。旧设置自动迁移，名称与数值样式保留。

「栏目之间的间距」控制 CPU、网络、FAN 等整个栏目之间的距离，默认 4 pt，支持 0–40 pt；「栏内参数间距」仍控制同一名称下多个数值的距离。所有栏目在一个原生状态栏区域中绘制，避免系统为每个独立项目附加留白。启用「风扇转速隐藏 RPM 单位」后，状态栏显示 `1640`，完整数据面板仍保留 RPM。CPU 各核心数据位于「此刻的 Mac」卡片之后、详细指标之前，无独立标题。

状态栏的网络数值使用十进制 KB / MB / GB 和三位有效数字，例如 `5.00KB`、`50.0KB`、`500KB`、`1.00MB`、`10.3MB`，代表每秒速度。上下行与普通栏内的网络参数均预留固定宽度，跨单位变化不会推动其他栏目。完整面板继续显示带 `/s` 的速度单位。设置中的预览直接由实际状态栏视图输出为 2 倍原生图像，字体、字号缩放、颜色、单位与间距均与实际状态栏一致。

### GPU 占用调查

本机 M1 Pro / macOS 27.0.1 的 `IOAccelerator.PerformanceStatistics` 提供 `Device Utilization %`，实测读到 10–12%，应用诊断快照也得到对应数值。整机 GPU 占用已可在总览和自定义栏目显示；默认栏目只有 CPU、MEM、网络，需要添加 GPU 参数。0% 是空闲，缺失字段才显示不可用。GPU 卡片现在说明读取字段与缺失原因；渲染器 / 平铺器不是总占用的替代值。

逐进程 GPU 现从 IOAccelerator 的递归子节点读取 `IOUserClientCreator` PID 与 `AppUsage[].accumulatedGPUTime`。两次采样的 GPU 纳秒差 / 实际秒数 × 100 得到执行时间占比；覆盖 Metal 和驱动记录的 GL/CL 工作，重叠执行可能超过 100%。按 registry entry ID 分别跟踪客户端，客户端新增/移除、计数器重置、首次采样和 PID 重用时不使用错误差值。没有 GPU 客户端的进程只有在驱动支持该计数器且基线有效时才显示 0；不支持的驱动显示不可用。可参考原作者的 [metalps 数据源说明](https://github.com/LoganBarnett/metalps#data-sources)。本机验证了 WindowServer、Chrome GPU Helper、Codex Service 等独立计数器，并通过短时 Metal 计算验证了本进程计数器递增。

这台 M1 Pro 没有提供 PG0R/PG0C GPU 功率键，因此接入 `libIOReport` 的 `Energy Model / GPU Energy`，识别 nJ/uJ/mJ/J 单位并用能量差 / 采样秒数得到平均 W。实时频率使用 `GPU Stats / GPUPH` 活跃档位驻留时间与 `voltage-states9` DVFS 频率表加权；只在档位可明确映射时输出，未映射的活跃档位不会被忽略。驱动保留但驻留为零的尾部档位不影响已知档位。接口可参考 [macmon 原始采样实现](https://github.com/vladkens/macmon/blob/main/src_lib/sources.rs)。GPU 能量模型本身已反映频率变化，不另套未经校准的固定 TDP。

整机 GPU 功耗与 GPU 占用仍作为设备指标展示；应用/进程功耗合并 CPU 内核能量与按 GPU 执行时间归属的 GPU 设备能量。列表摘要的“GPU 未计入合计”包括无进程归属、计数器不完整以及有 GPU 时间但 CPU 能量不可读的份额；这些部分不会转赠给其他应用。GPU 驱动能量模型与 SMC 均为机型相关接口；CPU SMC 键仅作总览传感器参考，不作为应用功耗预算。

更深入的 GPU 调度分析可使用 [Apple Instruments Metal System Trace / Game Performance](https://developer.apple.com/documentation/xcode/analyzing-the-performance-of-your-metal-app/)。当前采集无需管理员权限，没有常驻 root 服务、sudoers 修改或密码保存。

## 长截屏

在「截屏 → 区域截图」框选网页或 App 中需要滚动的区域，点击原生编辑器的「长截屏」。MacState 会暂时收起原本可见的主监控面板，并尝试将选区下的目标应用置于前台；完成或取消后按原状态恢复主面板（原先隐藏就保持隐藏），不隐藏其他应用窗口。

长截屏启动后同时显示两个区域：**左侧**是可拖动、可调整大小的独立原生实时预览窗，展示长图尺寸、已拼接段数，并支持预览内部滚动；**右侧**保留覆盖真实网页的蓝色透明取景框，完全穿透鼠标点击与滚轮。优先把预览放在取景区左边；空间不足时尝试右边、上下或其他显示器。默认**手动滚动**：可以在右侧蓝框内**向上或向下滚动**页面（建议每次约半屏），系统识别滚动方向并将尚未截取的内容补到左侧长图的顶部或底部；来回浏览已经采集的部分不会重复添加。预览不会每帧重组整张高分辨率图。面板可切换「开始自动滚动 / 切换手动滚动」、暂停/继续采集、完成并保存以及取消。即使进入自动滚动模式，目标应用也必须允许相应输入事件。点击「开始自动滚动」时，MacState 会检查系统是否允许发送模拟滚轮事件；必要时发起系统权限请求，如果未获授权会显示提示并维持手动模式。在系统设置的「隐私与安全性 → 辅助功能」中允许 MacState 后可重试，个别 macOS 版本需要重新启动应用以生效。手动滚动不需要额外辅助功能权限。

取景框本身不遮住截图像素，也不拦截目标窗口的鼠标事件；预览面板与取景框不覆盖采集区时均无需反复隐藏，只有用户拖动预览窗覆盖采集区后，采集期间才会临时隐藏预览以避免其写入图片。固定画面与重叠区域匹配失败时不会强行拼接可能错位的内容；过大的滚动跳跃、固定元素、完全重复的段落和动态页面仍可能需要重试。自动滚动按钮仍默认向下滚动，需要向上扩展时请手动向上滚动页面。完成时将原像素切片合成为图片，沿用截图设置保存/复制并记入「最近截图」。输出最多 1 亿像素并受 64 MiB 图片输入限制。macOS 15.2+ 采用 ScreenCaptureKit，较旧版本回退系统截图；除用户主动点击自动滚动时可能请求系统输入事件权限外，不会自动更改系统隐私设置。屏幕截取会将 AppKit 左下坐标准确转换为 Quartz/ScreenCaptureKit 左上坐标，避免取景框与实际截图区域错位；逐帧重叠检测保持原纵向像素精度，适合真实文字网页。已通过 WebKit 长网页的连续截图与合成自动测试；窗口穿透与用户桌面的真实输入授权和屏幕采集体验尚需实机验收。新版针对滚动过快、低对比文字和局部动画优化了可靠重叠匹配；采集间隔更短、图像比对移到后台，保存时会补采末帧以减少遗漏。若网页大片区域完全重复或单次滚动超过取景框约四分之三高度，仍可能无法安全判断重叠，请缩小滚动幅度。

## 数据边界

| 数据 | 来源 / 行为 |
| --- | --- |
| CPU 总占用 | Mach CPU tick 差值；所有逻辑核心平均，0–100%。 |
| 进程 CPU | `proc_pid_rusage` 时间差；Mach ticks 转纳秒，单核 100%，多线程可超过 100%。首次采样等待基线。 |
| 进程内存 | `ri_phys_footprint`；不把各进程内存之和当作整机内存。 |
| 进程估算功耗 | CPU 内核能量增量 + GPU 设备能量按实际执行时间归属；主值为当前区间，另列 30 秒 EWMA。GPU 部分为估算，缺失、重用、客户端变化及窗口错位时不冒充完整合计。 |
| 进程 GPU | `AppUsage` 逐客户端累计 GPU 执行时间差，按 PID 合并；驱动未公开或基线无效时不可用，不用整机占用替代。 |
| 温度/功率/风扇 | AppleSMC 只读 user client，属于硬件相关接口，不保证跨版本稳定。CPU 温度取 Tp/TC 键最高值，GPU 温度取 Tg/TG 最高值；原始键可独立查看。CPU 功率使用 PHPS/PCPC/PC0C 作传感器参考，系统功率使用 PSTR。映射随机型变化。 |
| CPU/GPU 频率 | CPU 仅 sysctl 标称值，Apple Silicon 通常缺失；GPU 优先驱动直接频率，回退 IOReport 活跃档位加权频率。完全空闲或无法映射档位时不显示猜测值。 |
| 网络 | 总览合计活动 en* 物理接口，避免 VPN/网桥重复计数；接口明细包含虚拟接口。接口重建/计数器回退时丢弃该次速率。 |
| 存储 | APFS 卷共享容器空间，容量不应跨卷相加。 |
| 权限 | 普通用户读取，受保护进程保留行并标明限制；不控制风扇，不结束用户进程。 |

H5 仅接受本地页面的原生消息，禁用网络连接和外部导航，对进程名称/路径和应用名称进行 HTML 转义。总览滚动历史只保存指标；使用记录另存降采样曲线及应用汇总，不保存每帧进程与传感器列表。

## 存储开发约定

每次开发前先阅读 [存储路线图](docs/STORAGE_ROADMAP.md) 与当前 specs 文档，阶段完成后更新真实进度。路线图保存了空间地图、分类、清理、应用空间、缓存、开发者空间、重复文件、媒体、历史与导出等后续需求。本次仅优化索引，不提前实现清理或读取文件内容。

索引采用整数文件 ID 和共享父目录路径；逻辑大小、实际分配大小、目录累计、硬链接、类型、创建/修改时间与权限提示保持。目录浏览仍按大小排序，搜索仍支持短中文与特殊字符。内部 ID 不作为永久历史身份。后续功能复用统一元数据，内容哈希、媒体属性、归属规则、风险与历史使用独立扩展表。

## 文件索引同步与搜索

文件元数据保存在每卷唯一的 `<卷标识>.sqlite` 中，使用 WAL。搜索和目录查询使用独立只读连接，增量更新使用写连接；每次目录读取最多提交 64 条元数据，重复文件事件按目录合并，FIFO 队列避免每次挑选目录都遍历全部待更新路径。相同文件仅大小/时间变化时原位更新，不重复写入名称搜索索引；硬链接仍使用完整归一化路径。删除按最多 32 个直接子项分组，单个子树保持原子删除以维护聚合与硬链接一致性，大子树删除仍可能耗时。

每 15 秒在独立后台连接执行非阻塞 PASSIVE WAL checkpoint，不再由日常增量提交触发自动 checkpoint；有活跃读写时保留 WAL，下次维护重试。分析页「立即同步」请求交付文件事件并处理待更新目录，也请求一次后台维护。目录读取仍最多 8 路并行，保持本地范围、权限提示、全部元数据、聚合、排序、分页与 Finder 定位。

启动时若发现旧双库方案的 `.changes.sqlite`，先将最终记录、删除标记、目录任务和事件游标耐久合入主库，关闭连接后退役缓存，再使用单库。合并失败保留恢复数据，不开始新扫描覆盖；正常升级无需全盘重建。程序退出期间的变化依靠每卷 FSEvents 已提交游标回放，丢失事件时局部/整卷核对。新方案不建立内存中的全量文件名副本，控制百万级文件下的常驻内存，不读取文件内容。

## 空间地图

入口：存储 → 文件分析 → 空间地图。按文件夹查看当前层最大的 256 个子项，较小项目及目录元数据汇总为独立区域；按文件类型汇总当前目录所有后代文件。方块面积使用索引中已去重的实际占用，零占用/过小项目仍可从右侧列表选择。单击选择，双击文件夹或在详情中进入；支持上一级、路径导航及 Finder 定位。类型/其他汇总区域不伪造文件路径。

地图使用同一元数据索引的只读快照，后台查询可取消，未增加扫描器和内容读取。提供手动刷新，文件事件同步时不自动重排正在操作的地图。当前范围很大时类型汇总可能需要等待；权限受限、APFS 共享块及快照会使地图总量与卷已用空间不同。按用户要求未运行测试，仅编译打包。

## 文件类型统计与大文件

存储 → 文件分析中提供独立「文件类型」和「大文件」入口。九类统计显示数量、实际占用、文件大小合计；按规则从现有元数据识别开发/模型/应用文件，空间地图类型视图共用同一规则。App 包内文件归入应用，源代码/配置归入开发，模型按常见扩展名/Models 路径推断；分类可随规则演进，不覆盖原始 kind，不读取内容。目录元数据单列，不重复计入文件分类。

大文件排行每页 100 项，无前 50 项上限；支持文件大小/实际占用切换、最小/最大 MiB、类型、修改日期区间及大小升降序。每行可在 Finder 定位、复制路径或移到废纸篓。移到废纸篓前原生窗口列出完整路径与大小并要求确认，确认后再次核对设备/inode/大小/修改时间；系统区域、App 包内部、非本地/占位文件禁止在此处理。不会永久删除，不自动申请权限；成功后更新索引和当前排行。逻辑大小与实际占用不同，物理占用排行不包含零占用的硬链接副本；统计和排行不等于可释放空间。按用户要求不运行测试，仅编译打包。
